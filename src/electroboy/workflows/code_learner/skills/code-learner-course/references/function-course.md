# Function Course

Explain the resolved symbol identity, owner, declaration, implementation,
signature, visibility, purpose, contract, inputs, outputs, mutations, side
effects, branches, errors, cleanup, callers, callees, state access, external
systems, concurrency, tests, dynamic limitations, and parent course links.

Set document `coverage_topics` to include `contract`, `control-flow`, `calls`,
`side-effects`, `errors`, and `tests`. Assign each section its `topic`. On the
call-graph section, copy the knowledge symbol's `call_edge_confidence` map so
the host and learner can distinguish verified, inferred, and unresolved edges.

Include an evidence-grounded Mermaid call graph when a meaningful caller or
callee is known. Visually distinguish verified static, inferred or dynamic,
and unresolved edges. Do not claim a complete graph when dispatch cannot be
resolved.

If caller, callee, state, or flow evidence is insufficient, emit a targeted
knowledge request instead of a shallow lesson.
