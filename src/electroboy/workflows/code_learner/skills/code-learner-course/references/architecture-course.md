# Architecture Course

Explain the selected repository as a complete working system: purpose and
users, external boundaries, public surfaces, components, extension families
and concrete implementations, dependencies, major runtime flows, state and
data ownership, topology, build, packaging, testing, operations, constraints,
tradeoffs, and uncertainty.

Include at least one evidence-grounded Mermaid component diagram and one
sequence diagram for a major runtime flow. Add any other supported Mermaid
diagram when it answers a distinct architectural question.

Link components and participants to Module courses when targets exist. Do not
let recent branch changes redefine repository-wide architecture.
