# Layered Knowledge

Generate structured evidence for later course construction. Horizontal
knowledge explains breadth at the current abstraction level. Vertical
knowledge follows selected behavior through modules, components, and exact
symbols. Keep the two dimensions explicit so learners can move across the
system or descend into implementation without losing position.

Use only frozen module and component IDs and accepted relationship IDs. Source
locators must resolve through supplied evidence. Preserve alternate, error,
dynamic, conditional, inferred, and unresolved behavior rather than inventing
certainty.

Mermaid diagrams may use any diagram type that clarifies the evidence.
Architecture requires a component or flowchart view and requires a sequence
diagram when an ordered cross-module flow exists. Every diagram must separately
list its canonical nodes and edges for validation before rendering. Knowledge
records may link to valid architecture, module, component, and function targets
but may not create those targets.
